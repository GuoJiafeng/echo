# 技术方案

## 1. 总体架构
Android App 负责系统音频采集、WebRTC 推流、内置 HTTP + WebSocket 服务；电脑浏览器通过局域网访问手机网页并接收音频。

## 2. 数据流
系统播放音频 -> AudioPlaybackCapture -> AudioRecord PCM -> WebRTC 音频轨 -> 浏览器 Audio 元素播放。

## 3. Android 音频采集原理
基于 MediaProjection 授权和 AudioPlaybackCaptureConfiguration，仅匹配 USAGE_MEDIA / USAGE_GAME。

## 4. WebRTC 推流原理
手机创建 PeerConnection 和音频 track，发送 offer；浏览器 answer 回传，双方交换 ICE 后建立 P2P 音频链路。

## 5. 信令流程
浏览器连 ws://phone-ip:8081/signaling，消息类型：offer / answer / ice-candidate / connected / error。

## 6. 启停流程
点击开始 -> 请求授权 -> 启动前台服务 -> 启动本地服务器与采集。
点击停止/服务销毁 -> 停采集 -> 释放 PeerConnection -> 关闭服务器。

## 7. 异常处理
权限拒绝提示、JSON 非法回 error、采集错误提示“当前音源 App 可能禁止被系统捕获...”。
